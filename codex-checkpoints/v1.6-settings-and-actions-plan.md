# v1.6 Settings and Actions Plan

## Base commit

`38c031f4bbe9992c4d21ddbccd7ae9084e217e97`

## Current architecture summary

- `Program.Main` initializes WinForms and runs a single `PetApplicationContext`.
- `PetApplicationContext` owns the single `PetForm`, notification-area icon, and existing tray menu commands.
- `PetForm` owns atlas loading, layered-window rendering, dragging, animation/state transitions, energy, curiosity, and the existing JSON settings load/save code.
- `PetSettings` currently stores the pet's X-position and active pet name in a local JSON file.
- Autonomous state selection and the tray menu's **Do Something** command currently contain separate random-to-state switches.
- Rendering creates a transparent 192 x 208 logical frame and passes it to `UpdateLayeredWindow`.

## Settings storage

Settings will continue to use the existing human-readable local file:

`%LOCALAPPDATA%\MarmaladeDesktopPet\settings.json`

The existing directory creation and safe exception handling will remain. Loading will normalize invalid values and malformed JSON will fall back to defaults without crashing. Saving will avoid rewriting the file when serialized values have not changed.

## Exact settings being added

- Preferred pet: `Marmalade` or `Merry`; extends the existing persisted active-pet setting.
- Always on top: Boolean, default `true`, applied immediately to `PetForm.TopMost`.
- Pet size: controlled choices `75%`, `100%`, `125%`, and `150%`, default `100%`.
- Wandering frequency: `Low`, `Normal`, or `High`, default `Normal`; implemented only by lengthening or shortening idle intervals, without changing state weights, movement, or other behavior logic.
- Start ClippyCat with Windows: Boolean, default `false`; implemented with the per-user `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value named `ClippyCat`, using the current executable path. Disabling removes only that value. Registry failures will leave the saved value unchanged and display a warning instead of crashing.

## Minimal action-system cleanup

- Add a small `PetAction` enum covering only actions/states that already exist.
- Add one dispatcher that maps a selected `PetAction` to the existing state-entry methods.
- Keep all existing state-entry methods, animations, rows, timings, and state-selection weights.
- Route both autonomous selection and **Do Something** through the dispatcher so future real actions have one clear extension point.
- Do not add or simulate any future action that lacks artwork/state support.
