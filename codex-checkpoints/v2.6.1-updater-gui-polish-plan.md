# ClippyCat v2.6.1 updater GUI polish plan

- Starting SHA: `441b4536cacae131a8790583a1fcd0665e22df25`
- Working tree: clean; local `main` and `origin/main` both point to the starting SHA.

## Current behavior

- Manual and automatic checks call `UpdateService.CheckForUpdateAsync` asynchronously. During a manual check, the tray item is disabled and reads `Checking for Updates...`.
- When an update is found, `UpdateDialog` displays release notes and begins download only after the user chooses **Download and Install**.
- The progress bar starts in marquee mode. When the installer response has a known content length, the existing byte progress switches it to continuous mode and displays a percentage.
- SHA-256 verification runs asynchronously in-process, but the dialog continues to say it is downloading until verification has already completed.
- After verification, the dialog currently says `SHA-256 verified. Opening the installer...`, launches the verified Inno Setup executable, closes the dialog, and only then asks the application context to exit ClippyCat.
- Network, checksum, and installer-launch errors already use a native message box and reset the dialog controls.

## Console-window risk review

- Runtime networking uses `HttpClient`; runtime hashing uses `SHA256.HashDataAsync`.
- No PowerShell, `cmd.exe`, shell script, console helper, or runtime packaging script is started.
- The only updater process launch is the downloaded installer path itself through `ProcessStartInfo` with `UseShellExecute = true`.
- This direct GUI executable handoff is the only relevant launch point. It will remain direct; no hidden shell workaround will be added.

## Minimal implementation plan

- Change updater progress reporting from a bare percentage to a small phase-aware value that distinguishes download from verification and allows an unknown percentage.
- Keep marquee progress during downloads whose size is unknown; switch to a normal percentage bar only when byte progress is available.
- Show `Downloading update...`, `Downloading update... N%`, `Verifying update...`, and `Starting installer...` at the appropriate stages.
- Disable both dialog buttons while downloading, verifying, and launching to prevent duplicate or conflicting input; restore the usable initial state after failures or cancellation.
- Preserve the existing direct installer launch and the existing application exit only after `Process.Start` succeeds.
