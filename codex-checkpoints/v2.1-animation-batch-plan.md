## Generation and recovery approach

- Use the built-in image generation workflow with production sprites and accepted source actions as explicit identity/style/pose references.
- Generate one action sheet at a time and inspect it before proceeding.
- If cat artwork is acceptable but arrives as RGB with a baked checker, recover only the connected checker/background into real alpha and preserve the cat rather than regenerating solely for transparency.
- Reject an action only for material cat-art failures such as broken anatomy, identity/style drift, unusable progression, or cleanup that would damage fur, paws, whiskers, eyes, or white markings.
- Preserve successful earlier actions if a later action fails its quality gate.

## Expected manifest and runtime changes

- Enable Merry Scratch at existing row 12 using the same 8-frame, 150 ms, 1600-2400 ms, weight-2 metadata already used by Marmalade.
- Add Yawn as a manifest-driven action at row 13 for each pet whose artwork passes validation.
- Preferred Yawn metadata: 8 frames, 220 ms/frame, 2200-3400 ms duration, autonomous weight 1, tray visible, and Do Something eligible.
- Add only the named `PetAction.Yawn`, `PetState.Yawn`, direct tray item, and light-energy state handling required by the current generic dispatcher architecture. No Yawn-specific rendering or timing branch will be added.
- Availability filtering will keep random/autonomous selection limited to pets with enabled artwork; no missing-art action may produce an autonomous popup.

## Expected atlas changes

- Merry row 12 will become populated with the approved Merry Scratch frames.
- Yawn will use row 13.
- If both Yawn packs pass, both atlases will expand from 1536 x 2704 to 1536 x 2912.
- Rows 0-11 will remain pixel-identical. Marmalade row 12 will remain pixel-identical. Merry row 12 changes only for the new Scratch art. Row 13 will contain only accepted Yawn source frames.
- The importer will run twice; the second run must perform no atlas rewrite and create no backup.

## Checkpoint sequence

1. Generate, extract, validate, and preview Merry Scratch.
2. Generate, extract, validate, and preview Marmalade Yawn.
3. Generate, extract, validate, and preview Merry Yawn using Marmalade Yawn as pose master.
4. Integrate only actions that passed visual and technical quality gates.
5. Validate importer idempotency, atlas pixel preservation, runtime wiring, build, and Git scope before commit/push.

## Explicitly out of scope

- Merry Stretch artwork
- Sit/Settle, Tail Flick, Roll/Flop, or any action other than Scratch and Yawn
- Redesigning either cat, pixel art, generic cartoon sprites, hard outlines, chibi proportions, or unrelated artwork changes
- Changes to existing action timing/rows except enabling Merry Scratch and adding Yawn
- Importer redesign, manifest schema changes, new packages, unrelated refactoring, settings, diagnostics, dragging, mouse look, wandering, Rest, Call Pet, Hide/Show, startup, or single-instance behavior
