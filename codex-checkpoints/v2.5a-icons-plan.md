# ClippyCat v2.5a icon plan

- Starting commit: `06ed552ae4d186b312ac1ed737888872cc1d5099`
- Starting worktree: clean on `main`, matching `origin/main`

## Current icon situation

- The project has no custom `.ico` files and no `ApplicationIcon` property.
- The tray `NotifyIcon` currently uses `SystemIcons.Application` and still has the tooltip text `Marmalade Desktop Pet`.
- The Inno Setup definition uses the executable for the uninstall display icon and shortcut icons, but has no branded `SetupIconFile`.
- Release publishing currently validates the executable, manifest, and both pet atlases only.

## Artwork plan

- Derive the main app icon from production Marmalade and Merry artwork, composing both recognizable heads together on a transparent square canvas.
- Create a separate high-contrast cat-head silhouette for the notification area, optimized for recognition at 16-24 px rather than reusing the detailed app artwork.
- Produce `Assets/Icon/ClippyCatAppIcon.ico` and `Assets/Icon/ClippyCatTrayIcon.ico` with 16, 20, 24, 32, 48, 64, 128, and 256 px entries. Retain one clean RGBA source PNG per icon only if useful for maintainability and validation.

## Integration locations

- `MarmaladeDesktopPet.csproj`: set the executable application icon and publish the runtime tray icon assets.
- `Program.cs`: load the tray-specific icon from `AppContext.BaseDirectory`, with the existing system icon as a safe fallback, and dispose the loaded icon at shutdown.
- `Publish-ClippyCat.ps1`: verify both icon assets are present in the standalone payload.
- `installer/ClippyCat.iss`: brand the setup executable explicitly; installed shortcuts and Add/Remove Programs continue to use the branded application executable.
