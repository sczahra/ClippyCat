## Stretch implementation

- Added `PetAction.Stretch` and `PetState.Stretch`.
- Added a `PerformPetAction` dispatcher case and `EnterStretch` state-entry method.
- Reuses existing pawing artwork: atlas row 7, 6 frames.
- Uses a 280 ms frame delay for a slower, deliberate setup/motion.
- State duration is randomized from 1.8 to 2.7 seconds.
- Has no horizontal movement and returns through the existing normal state-expiration path.
- Uses the existing one-point light-action energy cost group.

## Scratch implementation

- Added `PetAction.Scratch` and `PetState.Scratch`.
- Added a `PerformPetAction` dispatcher case and `EnterScratch` state-entry method.
- Reuses existing grooming artwork: atlas row 5, 8 frames.
- Uses a 150 ms frame delay so it reads as a quicker itch response than ordinary grooming.
- State duration is randomized from 1.6 to 2.4 seconds.
- Has no horizontal movement and returns through the existing normal state-expiration path.
- Uses the existing one-point light-action energy cost group.

Both pets use the exact same Stretch and Scratch logic. The existing diagnostics observe `PetState` names automatically, so transitions appear as `Stretch` and `Scratch` without any diagnostics-source change.

## Do Something integration

**Do Something** now chooses equally among seven supported actions:

- Wave
- Jump
- Groom
- Paw
- Review
- Stretch
- Scratch

Each has a 1-in-7 chance. Selection still enters the existing shared `PerformPetAction` dispatcher.

## Direct tray integration

- **Stretch** and **Scratch** are directly available beside Call Pet, Rest, and Do Something in the tray menu.
- Both items call `TriggerAction(PetAction)`, which delegates to the existing `PerformPetAction` dispatcher; no action logic is duplicated.

## Autonomous weighting changes

The tired branch is unchanged and does not select either new action.

At normal energy:

- Stretch: 3%
- Scratch: 3%
- Idle: reduced from 34% to 28%
- Every other existing action retains its previous probability.

At high energy:

- Stretch: 3%
- Scratch: 3%
- Idle: reduced from 12% to 6%
- Every other existing action retains its previous probability.

The new actions are therefore occasional and do not displace existing movement or active-action weights.

## Limitations and artwork recommendation

- Stretch is a timing-adjusted reuse of the pawing sequence, not a dedicated full-body stretch. A dedicated Stretch row would materially improve readability and is the higher artwork priority.
- Scratch is a faster reuse of grooming and is a reasonable short-term approximation, but dedicated self-scratch artwork would distinguish it more clearly from Groom.
- No sprite art was changed in this milestone.

## Manual testing checklist

1. Run `dotnet run` and confirm the About dialog reports Version 1.7.
2. Select Marmalade and choose **Stretch**, then **Scratch**, directly from the tray menu; confirm both actions begin immediately.
3. Invoke **Do Something** repeatedly until diagnostics show both `Stretch` and `Scratch` states through random selection.
4. Confirm Stretch uses the slower pawing-like sequence for roughly 1.8-2.7 seconds, remains horizontally stationary, and returns naturally to autonomous behavior.
5. Confirm Scratch uses the faster grooming-like sequence for roughly 1.6-2.4 seconds, remains horizontally stationary, and returns naturally to autonomous behavior.
6. Select Merry and repeat steps 2-5; confirm timing and behavior match Marmalade exactly while artwork identity remains Merry.
7. Let each pet run autonomously at normal/high energy long enough to observe occasional Stretch and Scratch transitions. Confirm they are uncommon and existing actions still dominate.
8. Lower energy into the tired range and confirm autonomous Stretch/Scratch do not occur there.
9. Verify the diagnostics log names the new states `Stretch` and `Scratch` without logging errors.
10. Recheck dragging, mouse look, Rest, Call Pet, Hide/Show, Pause Wandering, settings, all size options, always-on-top, startup setting, and layered transparency for regressions.
