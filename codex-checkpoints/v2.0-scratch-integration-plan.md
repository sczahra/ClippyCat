# v2.0 Marmalade Scratch Integration Plan

## Starting point

- Clean starting commit: `c28968b44a30e2b63db37a1c6d43f9e5a936617f`
- Both production atlases are currently 1536 x 2496 RGBA: 8 columns of 192 x 208 cells and 12 rows total.
- Recovered source frames are present at `Assets/actions/Marmalade/scratch/0.png` through `7.png`; each is 192 x 208 RGBA.

## Current manifest structure

`Assets/actions/actions.json` schema version 1 declares global cell dimensions, eight atlas columns, eleven protected base rows, and an `actions` array. Each action records `name`, `frameCount`, `frameMs`, minimum/maximum duration, autonomous weight, tray visibility, Do Something eligibility through `randomEligible`, and a per-pet `enabled` / `atlasRow` / `sourceFolder` entry.

Stretch is currently enabled for Marmalade at row 11 with six frames, 220 ms frame timing, a 1800-2600 ms duration, autonomous weight 3, tray visibility, and random eligibility. Merry reserves row 11 but is disabled. Scratch is currently a disabled zero-frame placeholder for both pets with no assigned row.

## Scratch metadata plan

- `name`: `Scratch`
- `frameCount`: 8
- `frameMs`: 150
- `minDurationMs`: 1600
- `maxDurationMs`: 2400
- `autonomousWeight`: 2, conservatively taken from the existing Idle bucket by the generic selector
- `trayVisible`: true
- `randomEligible`: true
- Marmalade: enabled, row 12, source folder `Marmalade/scratch`
- Merry: disabled, reserved row 12, source folder `Merry/scratch`

The existing `IsActionAvailable` filter makes Do Something and autonomous selection pet-aware. Therefore Scratch will enter those paths only for Marmalade; Merry cannot receive an autonomous or random pending popup. A direct Merry tray command will continue through the shared dispatcher and show `Scratch animation coming soon.`

## Row assignment and importer approach

- Keep protected rows 0-10 unchanged.
- Keep Stretch at row 11 unchanged.
- Assign Scratch to row 12 for both pets so atlas contracts remain aligned.
- Rebuild Marmalade row 12 from the eight recovered source frames without resizing or redrawing them.
- Expand both atlases from 1536 x 2496 to 1536 x 2704. Merry row 12 will be completely transparent because Merry Scratch remains disabled.
- Run the existing importer twice. The first run should create backups and write only because both atlases gain row 12; the second run should report both atlases unchanged and create no additional backup.
- Compare pre-import and post-import pixel hashes for rows 0-11, validate the new rows and source frames, and confirm the second-run atlas hashes are identical to the first-run hashes.

## Runtime changes

- Add `PetState.Scratch`, which the generic manifest dispatcher requires when an enabled definition is selected.
- Treat Scratch as the same light-energy action category as Stretch; no movement or action-specific dispatcher implementation is needed.
- Keep the existing Scratch tray command and shared `TriggerAction` / `PerformPetAction` path.
- Update About to Version 2.0 and minimally update the README status text.

## Explicitly out of scope

- Redrawing, regenerating, resizing, recoloring, or otherwise editing Scratch source art
- Merry Scratch artwork or enabling Merry Scratch
- Yawn or any other new action
- Changing Marmalade Stretch or Merry Stretch availability/timing
- Importer redesign, new packages, manifest schema changes, unrelated behavior/refactoring, settings, diagnostics, dragging, mouse look, wandering, Rest, Call Pet, Hide/Show, startup, or single-instance behavior
