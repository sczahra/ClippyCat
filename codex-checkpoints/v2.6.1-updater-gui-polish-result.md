## Updater GUI states

- Update checking remains asynchronous and is represented by the disabled tray item text `Checking for Updates...`; the update dialog is created only after an available release is found.
- Download begins with `Downloading update...` and a visible marquee progress bar.
- When GitHub provides installer content length, byte progress switches the bar to continuous mode and shows `Downloading update... N%` using real measured progress.
- If content length is unavailable, the bar remains marquee and no percentage is invented.
- SHA-256 hashing now explicitly reports `Verifying update...` with marquee progress.
- Successful verification transitions to `Starting installer...` before the direct installer launch.
- Both buttons are disabled throughout download, verification, and launch, preventing duplicate or conflicting actions.

## Error behavior

- Network, checksum, and installer-launch failures continue to show a concise native warning message.
- Failed operations do not mark the installer as launched, so ClippyCat remains running.
- The dialog resets to a usable state after failure or cancellation and does not remain stuck in a download state.

## Installer handoff and terminal-window review

- Networking remains in-process through `HttpClient`.
- SHA-256 verification remains in-process through `SHA256.HashDataAsync`.
- A runtime-source search found no PowerShell, `cmd.exe`, `conhost`, `.ps1`, or console-helper invocation.
- The only runtime process launch is the verified Inno Setup `.exe` path itself through `ProcessStartInfo` and `Process.Start`, with `UseShellExecute = true`.
- No hidden shell workaround, script, or console process was introduced.
- `InstallerLaunched` is set only after `Process.Start` succeeds; the application context exits ClippyCat only after that successful handoff.
