## Current product/runtime assumptions

- Current internal executable: `MarmaladeDesktopPet.exe`.
- Decision: keep the internal assembly/executable name to avoid unnecessary namespace, mutex, startup, and deployment risk. Installer, shortcuts, metadata, and About branding will use `ClippyCat`.
- Runtime assets are loaded from `AppContext.BaseDirectory`:
  - `Assets/Marmalade/spritesheet.png`
  - `Assets/Merry/spritesheet.png`
  - `Assets/actions/actions.json`
- Current project content glob also copies development action-source frames and legacy assets. It will be narrowed to the three runtime resources above for release/build output.
- Settings path: `%LOCALAPPDATA%\MarmaladeDesktopPet\settings.json`.
- Diagnostics path: `%LOCALAPPDATA%\MarmaladeDesktopPet\diagnostics.log`.
- Windows startup: current-user `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `ClippyCat`, containing the quoted `Application.ExecutablePath`. This already follows the installed executable rather than a development path.
- Single instance: named local mutex `Local\ClippyCat.MarmaladeDesktopPet.SingleInstance`; independent of repository location.

## Publish structure

- Add product/version metadata `2.5.0` to the project.
- Release target: `win-x64`, self-contained, folder-based, not single-file, trimming disabled, no aggressive WinForms/System.Drawing optimizations.
- Output: `artifacts/publish/win-x64/`.
- Runtime payload will contain the executable, self-contained .NET runtime dependencies, and only required production assets/manifest.
- `artifacts/` will be ignored by Git; the self-contained runtime payload will not be committed.

## Publish script

- Create `Publish-ClippyCat.ps1`.
- Resolve project paths from `$PSScriptRoot`.
- Delete only the resolved `artifacts/publish/win-x64` output after verifying it is under the project packaging directory.
- Run `Import-Actions.ps1`, then `dotnet publish` in Release for `win-x64` and self-contained folder deployment.
- Validate the executable, Assets folder, manifest, and both production atlases.
- Print the output path and total payload size; fail immediately on errors.

## Installer structure

- Create `installer/ClippyCat.iss` and `Build-Installer.ps1`.
- Product: ClippyCat 2.5.0; publisher: ClippyCat Project.
- Installation scope: per-user at `{localappdata}\Programs\ClippyCat`, with `PrivilegesRequired=lowest`.
- Rationale: ClippyCat stores user state and startup registration per user, so elevation and Program Files are unnecessary. This provides the simplest reliable install while retaining a normal Add/Remove Programs entry.
- Include the entire validated self-contained publish folder, excluding debug symbols.
- Add Start Menu shortcut, unchecked optional Desktop shortcut task, uninstall metadata, and direct post-install application launch.
- Output target: `artifacts/installer/ClippyCatSetup-2.5.0.exe`.
- Because ISCC is unavailable, `Build-Installer.ps1` will publish successfully and then stop with exact compiler/path guidance instead of installing anything.

## Risks and validation

- Self-contained publish is substantially larger than a framework-dependent build; generated payload remains ignored.
- Inno Setup is absent, so installer compilation and install/uninstall smoke testing cannot be completed here.
- WinForms layered rendering and tray behavior require a real desktop session; process startup can be smoke-tested, while tray/pet rendering and switching may still need human confirmation.
- Published layout must not contain Git data, checkpoints, scripts, legacy assets, or development action-source PNGs.
- Existing startup registry data will not be modified during packaging validation.
- No existing installation will be altered or uninstalled.

## Explicitly out of scope

- Automatic updates, GitHub Release/API calls, update notifications/downloads, silent updates, rollback.
- New animations, behavior changes, action-pipeline redesign, package additions, namespace renames, or assembly rename.
- Deleting LocalAppData settings/diagnostics on uninstall.
- Installing Inno Setup or committing self-contained runtime/installer binaries.
