## Settings implemented

- Preferred pet: Marmalade or Merry, using the existing persisted active-pet value.
- Always on top: Boolean, default on, applied immediately to the pet window.
- Pet size: controlled choices of 75%, 100%, 125%, and 150%, applied immediately with the original 192 x 208 aspect ratio preserved.
- Wandering frequency: Low, Normal, or High. This changes only idle-state duration ranges:
  - Low: 5.0-12.0 seconds
  - Normal: the existing 2.5-7.0 seconds
  - High: 1.5-4.5 seconds
- Start ClippyCat with Windows: Boolean, reversible and per-user.

The native WinForms Settings window is available as **Settings...** in the tray menu. Existing tray commands remain present.

## Storage and validation

Settings remain in the human-readable local file:

`%LOCALAPPDATA%\MarmaladeDesktopPet\settings.json`

The app creates the directory when saving. A missing or malformed file safely uses defaults. Loaded pet, size, and wandering values are normalized to their supported sets. Serialization now compares against the current file and writes only when the stored values differ.

Static verification confirmed:

- malformed JSON is caught by the existing safe load boundary and returns default settings
- only sizes 75, 100, 125, and 150 are accepted
- only Low, Normal, and High wandering values are accepted
- `Program.cs` has no `IsMerry` behavior branch; both pets still use the same behavior/state system

## Windows startup mechanism

The startup checkbox writes or removes only this per-user registry value:

- Key: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- Value name: `ClippyCat`
- Value data when enabled: the quoted current application executable path

Disabling deletes only the `ClippyCat` value and tolerates it already being absent. Registry exceptions are returned to the Settings window, which restores the checkbox to the saved value and displays a warning without crashing. No administrator access is used.

## Action-system cleanup

- Added a small `PetAction` enum containing only actions/states already supported by existing sprite rows.
- Added `SelectNextAutonomousAction` to preserve the existing energy-dependent random weights while returning a selected action.
- Added `PerformPetAction` as the single action-to-existing-state dispatcher.
- Both autonomous selection and the tray menu's **Do Something** command now use that dispatcher.
- Existing state entry methods, weights, energy logic, animation timings, dragging, mouse-look, and click reactions remain intact.

No speculative actions or sprite rows were added.

## Rendering and size handling

Animation frames continue to be composed on the original transparent 192 x 208 logical canvas. The selected size is applied only to the final 32-bit ARGB bitmap passed to `UpdateLayeredWindow`, using high-quality bicubic scaling. The Form size and layered bitmap size stay synchronized, so dragging coordinates and the window's transparent hit-test surface scale together. Immediate size changes preserve the pet's horizontal center and bottom anchor where screen bounds allow.

## Known limitations

- Layered-window transparency, alpha-edge hit testing, and drag feel at every scale require real Windows runtime verification.
- The registry toggle was statically verified but not exercised automatically, to avoid changing the user's actual Windows startup configuration during the build.
- The startup entry points to the current executable location. If the application is moved, the user should turn the option off and on again to refresh the path.
- The Settings window reflects the saved startup preference; unrelated external edits to the registry are not automatically reconciled.

## Manual testing checklist

1. Run `dotnet run`, open the tray menu, and confirm **Choose Pet**, **Hide/Show**, **Pause Wandering**, **Call Pet**, **Rest**, **Do Something**, **Settings...**, **About**, and **Quit** are present and functional.
2. Open **About** and confirm it displays Version 1.6.
3. Open **Settings...**, switch between Marmalade and Merry, close and relaunch, and confirm the preferred pet persists.
4. Toggle **Always keep pet on top** both ways and confirm the change applies immediately and survives relaunch.
5. Test 75%, 100%, 125%, and 150%. At each size, confirm aspect ratio, transparency, click response, dragging, floor snapping, and mouse-look remain correct.
6. Test Low, Normal, and High wandering frequencies for several idle cycles. Confirm only the idle interval changes; action types, movement speed, energy behavior, and both pets' shared behavior remain unchanged.
7. Enable **Start ClippyCat with Windows** and verify the quoted executable path appears only at `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `ClippyCat`. Disable it and confirm only that value is removed.
8. Temporarily replace `settings.json` with malformed JSON, launch the app, and confirm defaults load without a crash. Restore or remove the test file afterward.
9. Put unsupported pet, size, and wandering values in `settings.json`, launch, and confirm they normalize to Marmalade, 100%, and Normal.
10. Use **Do Something** repeatedly and allow autonomous actions to run for several minutes with each pet; confirm all existing animations still occur and diagnostics continue logging normally.
