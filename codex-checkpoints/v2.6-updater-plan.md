# ClippyCat v2.6 updater plan

- Starting commit: `72db017547595ee77e73fb77170c8758d02eb69f`
- Starting worktree: clean on `main`, synchronized with `origin/main`
- Official repository: `https://github.com/sczahra/ClippyCat`

## Current version and packaging sources

- Application/product metadata is defined in `MarmaladeDesktopPet.csproj` as `2.5.0` (`Version`, informational, assembly, and file versions).
- The About dialog in `Program.cs` separately displays `Version 2.5`.
- Diagnostics bootstrap separately reports `2.5`.
- `installer/ClippyCat.iss` separately defines `2.5.0` and a versioned output filename.
- `Build-Installer.ps1` separately expects `ClippyCatSetup-2.5.0.exe`.
- `Publish-ClippyCat.ps1` creates the self-contained `win-x64` payload after running the action importer.
- `Build-Installer.ps1` publishes, discovers Inno Setup only from PATH/Program Files, compiles the installer, and validates the installer executable. It does not create a checksum file.

## Current application structure

- `PetApplicationContext` owns the tray icon and context menu. `Settings...` and `About` are adjacent near the end of that menu.
- Startup shows the pet immediately and then enters the WinForms message loop.
- Start with Windows uses `Application.ExecutablePath` in the current-user Run key, so an installed build continues to reference its installed executable.
- Settings and diagnostics live under `%LOCALAPPDATA%\MarmaladeDesktopPet` and are outside the installer directory.

## Proposed updater architecture

- Set assembly/product version metadata to `2.6.0` in the project file and derive About, diagnostics, and updater installed-version text from assembly metadata.
- Let `Build-Installer.ps1` read the project version and pass it into Inno Setup, removing duplicated filename/version logic from the build script while keeping a safe `2.6.0` installer-source default.
- Add a focused `UpdateService.cs` using only BCL APIs. It will query `https://api.github.com/repos/sczahra/ClippyCat/releases/latest`, normalize `vX.Y.Z`/`X.Y.Z` tags with `System.Version`, reject drafts/prereleases/malformed or non-newer releases, require exactly named EXE and SHA256 assets, download via temporary files, parse and verify SHA-256, and launch only a verified installer through normal shell execution.
- Add a small native `UpdateDialog.cs` that presents installed/available versions, a capped plain-text release-note summary, Download and Install/Later actions, and responsive download status.
- Add `Check for Updates...` near Settings/About. Manual checks show friendly errors and disable their menu item while active.
- Start one silent asynchronous check after the pet is visible and a short delay. It will never show network errors or missing-release-contract popups, and it will notify at most once per application session.
- Use the existing diagnostics logger for check, version, download, verification, mismatch, launch, and error milestones without logging release bodies or user data.
- Keep settings in their existing LocalAppData path. Exit only after `Process.Start` successfully launches the verified installer.

## Packaging changes

- Extend Inno Setup discovery to `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`.
- Generate `ClippyCatSetup-2.6.0.exe.sha256` beside the installer with a simple `<64-hex>  <filename>` format accepted by the updater.
- Display installer path, size, SHA-256, and checksum path after a successful installer build.
- Document GitHub Release tag/title/asset steps without automatically publishing a release.

## Risks and mitigations

- GitHub/network failures: bounded timeout, cancellation-aware async calls, concise manual errors, silent startup failures.
- Malicious or malformed release metadata: stable latest endpoint only, draft/prerelease rejection, semantic version parsing, exact asset names, HTTPS URLs, and no arbitrary executable selection.
- Corrupt/tampered installer: download to incomplete files, strict checksum parsing and SHA-256 comparison, delete invalid installer, never execute on mismatch.
- UI stalls or repeated prompting: async I/O, disabled menu state during work, one startup check and one update notification per launch.
- Installer replacement conflicts: launch normally without bypasses, then close ClippyCat only after launch succeeds.
- Test leakage: helper tests exercise pure parsing/selection/integrity methods; no mock endpoint is shipped.
