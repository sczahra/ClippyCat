# v1.7 Dedicated-Art Preparation Plan

## Base commit

`27a99faf1d23912be1799c8c956c01078f777943`

The working tree contains the expected uncommitted v1.7 changes in `Program.cs`, `README.md`, and the v1.7 Stretch/Scratch checkpoint files.

## Current reused-row implementation

- `PetAction.Stretch` dispatches to `EnterStretch`, which reuses the Pawing animation (row 7, 6 frames) for 1.8-2.7 seconds with a special 280 ms frame delay.
- `PetAction.Scratch` dispatches to `EnterScratch`, which reuses the Grooming animation (row 5, 8 frames) for 1.6-2.4 seconds with a special 150 ms frame delay.
- Temporary `PetState.Stretch` and `PetState.Scratch` values support those borrowed animations, including light-action energy handling.
- **Do Something** currently includes both actions in its seven-action random selection.
- Autonomous selection currently gives each action 3% at normal and high energy, taken from the original Idle probability.
- Direct **Stretch** and **Scratch** tray commands use the shared `TriggerAction` / `PerformPetAction` path.

## Why the reused implementation is being removed

Pawing does not depict stretching, and Grooming does not clearly depict scratching. Re-labeling those rows and adjusting their timing makes the commands appear complete when their dedicated poses do not yet exist. The temporary state and timing logic should be removed so future artwork can be integrated without retaining misleading behavior.

## Action plumbing to preserve

- `PetAction.Stretch` and `PetAction.Scratch`
- Direct **Stretch** and **Scratch** tray menu items
- The shared public `TriggerAction(PetAction)` entry point
- `PerformPetAction` dispatcher cases for both actions
- A clear future path for **Do Something** and autonomous selection to return these actions once dedicated rows exist

## Exact code changes planned

1. Remove `PetState.Stretch` and `PetState.Scratch` because no animation state remains without dedicated artwork.
2. Remove the borrowed-row `EnterStretch` / `EnterScratch` methods, their special frame delays, and their temporary energy cases.
3. Keep both dispatcher cases, but have each show a small friendly "animation coming soon" message without changing pet state.
4. Restore **Do Something** to its original five implemented actions so random selection never opens a placeholder message.
5. Remove Stretch and Scratch from autonomous selection and restore the original 34% normal-energy and 12% high-energy Idle shares; preserve every other existing probability.
6. Keep About at Version 1.7 while making its description accurately reflect command preparation for dedicated artwork.
7. Update README wording so the commands are documented as present while their dedicated animation artwork is pending.
8. Build and record the outcome in `codex-checkpoints/v1.7-dedicated-art-prep-result.md`.

## Explicitly out of scope

- Creating, editing, regenerating, resizing, or replacing either pet sprite sheet
- Choosing or inventing dedicated sprite rows, frame counts, or animation timing
- Adding packages, dependencies, installer work, or additional actions
- Redesigning or reorganizing the behavior engine or dispatcher
- Changing settings, diagnostics, dragging, mouse look, existing animations, pet identity, or unrelated behavior
- Refactoring or cleanup unrelated to removing the temporary reused-art implementation
