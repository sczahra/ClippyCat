`5ffab12c8c7ebe7a037593ef1209e320c65464eb`

## Atlas facts

- Marmalade atlas: 1536 x 2288 pixels, 32-bit ARGB PNG
- Merry atlas: 1536 x 2288 pixels, 32-bit ARGB PNG
- Atlas cell size: 192 x 208 pixels
- Target diagnostic cell: zero-based row 6, frame/column 3 (`x=576`, `y=1248`)

## Existing diagnostic evidence

- 73 compared frames
- Average size error: about 5.2%
- Average center error: about 0.5 px
- Average bottom error: about 1.4 px
- Worst size outlier: row 6, frame 3 at about 8.8%

## Exact inspection plan

1. Extract only Marmalade and Merry row 6, frame 3 into `codex-checkpoints/v1.5-analysis/`, preserving each 192 x 208 cell and transparency.
2. Measure the alpha-based non-transparent bounds for each frame using the same alpha threshold and two-pixel sampling approach as the v1.4 diagnostics, then confirm the result with full-pixel bounds so the proposed operation is not based on a sampling artifact.
3. Record left, top, right, bottom, width, height, center X, center Y, bottom alignment, and percentage size difference.
4. Inspect the extracted pair visually and classify the mismatch as scale, vertical placement, horizontal placement, silhouette/artwork shape, transparent padding, or a combination.
5. Edit only Merry row 6, frame 3 if a small geometric correction is clearly safe. Preserve the 192 x 208 cell, transparency, pose, shadow, eye colors, white coat/gray head patch, adjacent cells, and 1536 x 2288 atlas dimensions.
6. Re-extract and remeasure the corrected cell.
7. If the correction succeeds with low risk, calculate at most the next three worst frame-level size outliers. Do not edit any that require repainting or differ for artistic/silhouette reasons.
8. Verify the final Merry atlas exists, remains 1536 x 2288 with transparency, and that no source or behavior files changed.

## Explicitly out of scope

- Whole-sheet regeneration or any whole-atlas transform
- Global resize, shift, crop, recolor, or style change
- Marmalade artwork changes
- Behavior or animation-logic changes
- Source-code changes, package additions, or unrelated refactoring
- Editing more than a very small number of clearly geometric frame outliers
- Automatic repainting of pose, shadow, eyes, coat, or gray head patch

## Cause and proposed minimal correction

Horizontal placement and bottom alignment are already good. The mismatch is a combination of slightly smaller scale and a genuine silhouette/artwork difference: Merry's body and tail are naturally slimmer than Marmalade's, so matching Marmalade's width exactly would over-enlarge or distort Merry. Transparent padding is a consequence of the smaller silhouette, not the primary cause.

A low-risk geometric correction is justified for the scale component only: uniformly enlarge Merry's complete antialiased content by approximately 4%, centered horizontally and anchored to Marmalade's bottom edge. The integer destination bounds will be `(29,4)` through exclusive `(163,203)`, or 134 x 199 pixels. This preserves Merry's aspect ratio to rounding precision, pose, shadow, colors, and transparency while leaving the remaining silhouette difference intact. Only the target cell will be replaced.
