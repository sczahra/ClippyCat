## Manifest schema

`Assets/actions/actions.json` uses schema version 1 and records:

- global cell width/height, atlas column count, and protected base-row count
- action name
- frame count and frame duration in milliseconds
- minimum and maximum state duration
- autonomous weight
- tray visibility
- **Do Something** eligibility
- per-pet enabled state, atlas row, and source folder

## Importer behavior

`Import-Actions.ps1`:

- shows five visible progress stages and a final summary
- validates schema version, atlas/cell dimensions, action uniqueness, per-pet entries, protected rows, unique row assignments, duration/frame metadata, and autonomous-weight capacity
- requires sequential `0.png`-style files for enabled art and an exact manifest frame count
- requires real PNGs with alpha, at least one visible pixel, at least one transparent pixel, and dimensions no larger than 192x208
- centers smaller frames in their cells without cropping and copies exact-size frames without resampling
- permits absent source folders for disabled/pending pet actions
- preserves rows 0-10 at the raw pixel level
- rebuilds only manifest-declared dedicated rows and refuses to overwrite undeclared dedicated rows
- keeps unused cells and disabled reserved rows transparent
- compares the complete prospective atlas against the current atlas before writing
- supports native `-WhatIf`, which performs validation and reports changes without writing anything
- produces no separate generated-state file; explicit row assignments plus full pixel comparison keep output deterministic with less state

## Backup behavior

Before any real atlas replacement, the importer copies the current atlas to:

`Assets/backups/<Pet>-spritesheet-<timestamp>.png`

If the prospective atlas is unchanged, it creates neither a backup nor a rewritten PNG. Backups are excluded from build output and ignored by Git. The timestamp is the only intentionally variable data, and it exists only when an atlas truly changes.

## Action-definition refactor

- Added lightweight `ActionManifest`, `ActionDefinition`, and `ActionPetDefinition` models.
- The app loads `Assets/actions/actions.json` at startup and validates its runtime atlas contract.
- Manifest-backed actions use one generic dispatcher path to obtain row, frame count, min/max duration, state name, and active-pet availability.
- Manifest frame timing is read generically by `GetFrameDelay`; Stretch-specific row, frame-count, timing, entry-method, and `HasStretchArtwork` code were removed.
- **Do Something** automatically includes enabled definitions whose `randomEligible` value is true.
- Autonomous selection automatically consumes enabled definition weights from the existing Idle bucket, leaving all built-in action thresholds unchanged.
- `trayVisible` controls the existing dedicated action menu items.
- If the manifest is unavailable or invalid, existing built-in actions continue and dedicated commands fall back to pending messages.

`PetAction` and `PetState` remain named enums by design; a new action needs only matching enum names plus source frames and manifest data, not another row/timing/rendering implementation.

## Adding a future action

1. Add matching names to `PetAction` and `PetState` if the action is new.
2. Add sequential transparent frame PNGs under `Assets/actions/<Pet>/<action>/`.
3. Add the action and per-pet availability to `Assets/actions/actions.json`.
4. Run the dry-run importer, then the real importer, build, and visually test.

No additional row constants, frame-count constants, timing switch cases, state-entry methods, or per-action selection branches are required.
