# v1.9 Animation Pipeline Plan

## Starting point

- Commit: `0180f5110cfc0c7f0beb90988df53bff80946de4`
- Working tree: clean
- Marmalade atlas: 1536x2496 RGBA
- Merry atlas: 1536x2496 RGBA
- Runtime cell contract: 192x208, 8 columns
- Marmalade Stretch currently uses hardcoded row 11, 6 frames, 220 ms/frame, and a 1.8-2.6 second duration.
- Merry Stretch and Scratch for both pets currently use the shared dispatcher but show pending-art messages.

## Current hardcoded action architecture

- `PetAction` and `PetState` name actions and states.
- Dedicated Stretch metadata is split across `StretchRow`, `StretchFrames`, `EnterStretch`, `GetFrameDelay`, `HasStretchArtwork`, manual random selection, and autonomous thresholds.
- The shared `TriggerAction` / `PerformPetAction` path is useful and will remain.
- Existing built-in actions use established state-entry methods and weighting; they will not be migrated in this milestone.
- Atlases are runtime assets copied by the existing `Assets\**\*` project content rule, but there is no durable individual-frame source or repeatable action-row importer.

## Proposed data-driven structure

- Add `Assets/actions/actions.json` with a small schema containing the cell/atlas contract and action definitions.
- Each action definition will include name, frame count, frame duration, min/max action duration, autonomous weight, tray visibility, random-action eligibility, and per-pet enabled/atlas-row/source-folder metadata.
- Add lightweight `ActionManifest`, `ActionDefinition`, and `ActionPetDefinition` models in `Program.cs`.
- Load the manifest at startup. A manifest-backed action will enter its named `PetState` using manifest row/frame/timing data when artwork is enabled for the active pet; otherwise it will retain the friendly pending-art message.
- Derive dedicated-action random eligibility, autonomous weight, availability, and frame delay from the manifest. Existing built-in selection probabilities remain unchanged; manifest weights are taken only from existing Idle shares.
- Keep named `PetAction` / `PetState` values rather than introducing string-based plugins.

## Source-art and importer plan

- Create `Assets/actions/Marmalade/stretch/0.png` through `5.png` by copying the already-approved 192x208 cells from Marmalade atlas row 11 pixel-for-pixel. This creates the durable source of truth without new or modified artwork.
- Represent Merry Stretch and Scratch as disabled/pending entries; missing source folders/files are allowed only when the pet entry is disabled.
- Add `Import-Actions.ps1` using built-in Windows `System.Drawing` only—no NuGet or external module.
- Validate manifest shape, unique actions/row assignments, atlases, PNG format, alpha, frame dimensions, sequential frame names/counts, enabled-pet source folders, and autonomous-weight limits.
- Accept exact 192x208 frames or smaller transparent frames centered without cropping. Reject oversized, opaque-only, empty, malformed, or misnumbered input.
- Preserve base rows 0-10 pixel-for-pixel, rebuild only manifest-declared dedicated rows, fail on undeclared existing dedicated rows, and keep unused cells transparent.
- Compare prospective atlas pixels before writing. If unchanged, skip both write and backup; if changed, create a timestamped `Assets/backups/<pet>-spritesheet-*.png` backup first.
- Implement native `-WhatIf` support: validate and report intended changes while writing no atlases or backups.
- Avoid a generated-state file for now because direct pixel comparison and manifest row assignments provide deterministic idempotence with less state.

## Convenience workflow plan

- Add `Build-And-Run-Actions.ps1` rooted at `$PSScriptRoot`.
- It will unblock the two local scripts where permitted, run the importer, run `dotnet build`, stop immediately on failure, and launch the built app with clear `[1/N]` progress output.
- Exclude `Assets/backups/**` from runtime content so safety backups are not copied into build output.

## Backward-compatibility plan

- Marmalade Stretch retains row 11, six frames, 220 ms/frame, 1.8-2.6 second duration, 3% normal/high autonomous weight, and manual/random eligibility.
- Merry Stretch remains unavailable and cannot create autonomous or **Do Something** popups; its direct tray command remains visible and pending.
- Scratch remains visible in the tray, disabled for both pets, and pending.
- Existing built-in actions, atlas rows 0-10, behavior thresholds, tray wiring, settings, diagnostics, rendering, and dependencies remain unchanged.
- Running the importer twice against unchanged sources will make no second atlas write or backup.

## Explicitly out of scope

- New, regenerated, repainted, or transformed pet artwork
- Merry Stretch or any Scratch artwork
- Migration of every built-in action into the manifest
- Dynamic enum/plugin loading or a broad plugin architecture
- New packages, external modules, installer work, UI redesign, or behavior-engine redesign
- Changes to dragging, mouse look, settings, diagnostics, startup, single-instance behavior, layered transparency, or unrelated animation logic
